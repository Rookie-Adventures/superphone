## 一、选机原则

矩阵不是为了凑数，是为了**尽早撞见失败**。选机标准：

1. **覆盖 OEM 差异**——国产 ROM（MIUI/ColorOS/OriginOS/HarmonyOS）对 Telephony 的裁剪差异远大于 Android 版本差异
2. **覆盖 Android 大版本**——10 / 11 / 12 / 13 / 14 / 15 各至少 1 台
3. **覆盖通信形态**——VoLTE 开/关、VoWiFi、双卡、物理 SIM / eSIM
4. **优先手头已有的机器**——先测现成的，别一上来就采购

## 二、建议清单（待 E03 确认后调整）

| # | 定位 | 建议机型方向 | Android | 测点价值 |
|---|---|---|---|---|
| 1 | 基线 | Pixel 系列（原生，AOSP 行为最接近文档） | 13–15 | API 是否存在、原生行为基准 |
| 2 | 国产旗舰 | 小米 / Redmi（MIUI/HyperOS） | 14–15 | 国内最大存量，ROM 裁剪激进 |
| 3 | 国产旗舰 | OPPO / 一加（ColorOS） | 14–15 | Telephony 定制多 |
| 4 | 国产旗舰 | vivo（OriginOS） | 14–15 | 同上 |
| 5 | 华为 | HarmonyOS 4 / NEXT | 12–14 | 非 AOSP，API 可能直接缺失 |
| 6 | 中低端 | 千元机（联发科 SoC） | 12–13 | 低端 SoC 音频通路实现差异大 |

> 起步建议：先凑 **6 台**（第 1、2、5、6、7、8 项），把跨度拉开。测出第一台成功机型后，再围绕它补充同系列机型做稳定性验证。

字段口径：
- **API存在**：三个 API 是否都能反射到（是 / 部分 / 否）
- **下行提取** / **上行注入**：成功 / 抛异常 / 静默失败（拿到对象但无数据）
- **延迟**：从 PCM 产生到可被读出的本地 I/O 延迟，**不含网络**
- **稳定性**：连续通话保持时长与是否出现中断
- **结论等级**：已确认 / 推断 / 待验证——必须与 [事实分级清单](./事实分级清单.md) 一致
