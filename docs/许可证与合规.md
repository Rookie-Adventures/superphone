## 二、AGPL-3.0 的实际影响（重点）

本产品为**私域分发**（不上架、不推广、手动发安装包），因此：

- AGPL 第 13 条的"网络交互须提供源码"义务在私域场景下**实际触发面有限**，但仍应保留"修改版源码对用户可得"的习惯——**这是省心，不是可选项**。
- **真正危险的是混仓**：一旦 RemotePhone 的二开代码与其他私有项目进同一个仓库或构建单元，AGPL 的传染性会波及整个衍生作品。

### 因此立下硬规矩

1. 本仓库**独立存在**，不与任何其他项目共仓、不共用构建产物。
2. 引入任何第三方依赖前，先在本页登记许可证，E09 确认无传染风险后方可使用。
3. 分发安装包时，随附获取源码的方式说明（哪怕只是一句"联系索取"）。

## 三、隐私红线

| 项 | 约束 |
|---|---|
| 通话音频 | **默认不保存、不上传、不训练**。PoC 阶段落本地文件仅用于验证可听，验证完即删 |
| 设备指纹 `fp` | `HMAC(device_hwid, salt)`，轻量不可逆；不强求 Keystore 证明（私域足够） |
| 会话鉴权 | 不能只依赖设备 ID——设备 ID 可伪造，须叠加会话鉴权 |
| 变声模型 | 禁止声音克隆、声纹训练、用户上传声音模型。仅 4 组固定音色 |
